## 2. 이번 검수에서 새로 찾은 것 — 장과 장 이음매의 어미 3연속, 그리고 자기 채점 실패

이월 목록에는 없던, 이번 검수 자체에서 발견한 것을 따로 적는다.

**장-장 이음매 어미 3연속 일곱 곳.** 브리프가 요구한 대로 열일곱 개 이음매(앞 장의 마지막
문장 → 다음 장의 첫 문장, 코드 블록·표 셀 제외)를 전수 조사해, 7곳에서 `-니다` 계열 어미가
3연속 걸리는 것을 확인했다 — 1장→2장, 5장→6장, 7장→8장, 9장→10장, 11장→12장, 12장→13장,
14장→15장. 각 장은 개별 리뷰를 통과했지만 장 사이의 이음매는 그때까지 검사 대상이 아니었다
(각 장 태스크가 "자기 장 안"만 셌다). **전부 고쳤다** — 대부분 진입하는 장의 첫 문장을,
두 곳(5장→6장, 12장→13장)은 앞 장 퀴즈 해설의 마지막 문장을 체언 종결로 바꿔 사슬을 끊었다
(뒤 문장이 앞 장의 표·문구를 그대로 인용한 곳이라 손대지 않았다). 열일곱 개 전수 표와 수정
전/후 대조는 `task-20-report.md` §4에 있다.

**이 발견 자체가 한 차례 불완전했다.** 1차 검수에서 열일곱 개를 "전부 세었다"고 보고했는데
실제로는 1장→2장 이음매(3연속)를 놓쳤다 — 컨트롤러 리뷰가 잡아 재검수로 찾아 고쳤다. 이
프로젝트에서 자기 채점("전부 확인했다"는 보고)이 실제와 어긋난 것이 **일곱 번째**이고
(Ruling L·Task 15·Task 18이 앞선 사례들을 기록해 두었다), 이번엔 그것이 **최종 게이트에서**
났다. 다음 문서를 만드는 사람을 위한 패턴: **"전부 세었다"류의 완결형 주장은 실제로 표를
만들어 하나씩 지워 가며 검증했을 때만 쓸 것** — 눈으로 훑고 "다 됐다"고 쓰는 방식은 최종
검수 단계에서도 똑같이 틀린다.

## 3. 회수 구조 — spec §6 표 대조

여덟 행 중 일곱은 심은 곳과 거두는 곳이 본문에 실제로 있는 것을 확인했다. 한 행은 명시적
연결을 찾지 못했다.

- **미확인: "2장 계정은 격리 단위 | 10장 책임 분계선 → IAM 문서".** 2장은 "계정은 격리
  단위이자 청구 단위"를 분명히 세운다(`:721,726,735`). 그런데 10장(관리형/책임 분계선) 본문
  어디에도 "계정"이나 "격리"라는 단어가 나오지 않는다 — 10장은 RDS의 책임 분계선(온프렘·
  EC2·RDS 세 갈래, 열한 줄)이라는 전혀 다른 종류의 경계를 다룬다. **판정: 포기하고 기록한다.**
  두 경계(계정의 격리 vs. 관리형 서비스의 책임 분계선)를 억지로 연결하는 문장을 10장에
  끼워 넣으면, 이미 Critical·Important 0건으로 승인된 10장의 서사(장면→표→이름)에 어색한
  삽입이 될 위험이 크다고 판단했다. spec §6 표 자체가 다소 느슨하게 짝지은 행일 가능성도
  있다.
- 나머지 일곱 행은 전부 확인됨: Hero 아홉 개 목록↔1장·15장 / 3장 AZ 갇힘↔7장·9장 / 3장
  글로벌인 것들↔8장 / 5장 IP 변경↔7장 EIP↔12장 요금 / 6장 볼륨 생존↔12장 정체불명 EBS / 4장
  ARN↔13장·IAM 문서 / 1장 따로 과금↔12장 청구서.

## 4. 브라우저 실측을 하지 못했다

`mcp__chrome-devtools__new_page`/`list_pages` 호출이 전부
`"The browser is already running for .../chrome-profile. Use --isolated to run multiple
browser instances."` 오류를 반환했다 — 동시에 다른 세션이 같은 크롬 프로필을 점유하고 있어
새 페이지를 열 수 없었다. `--isolated`나 별도 `userDataDir`를 지정하는 파라미터는 `new_page`
도구에 노출되어 있지 않았다. 다른 세션의 브라우저를 강제로 종료하는 것은 그 세션의 작업을
방해할 위험이 있어 시도하지 않았다.

실측하지 못한 항목과, 대신 사용한 정적 근거:

- **저장소 키 격리(Step 3).** `localStorage` 호출은 파일 전체에서 단 세 곳뿐이고(`LS.get`/
  `LS.set` 내부의 두 곳, 초기화 버튼의 한 곳) 전부 `"awsbase:"` 접두어를 하드코딩한다. 코드
  구조상 `netsec:`/`iamtut:` 키에는 애초에 접근할 수 없다 — 런타임 확인 없이도 정적으로
  보장된다.
- **외부 요청 0건(Step 2).** `<link>` `<script src>` `<img>` `@import` `fetch(` `XMLHttpRequest`
  `http://` `https://` 전부 0건. Prism 하이라이터는 인라인 스크립트로 임베딩돼 있다.
- **모바일 드로어(Step 9).** `@media(max-width:980px)` 안에서 `#sidebar{z-index:160}`이고
  `#scrim{z-index:150}`(전역, 미디어 쿼리 밖 정의) — `aws_network_security.html`이 고친 값과
  동일한 순서로 상속돼 있다. TOC 링크 클릭 핸들러(`:1772`)가 `#sidebar`와 `#scrim`의 `open`
  클래스를 둘 다 지운다 — `2026-08-14-known-issues.md` §1이 지적한 "핸들러가 한쪽만 지운다"
  버그의 패턴이 없다. **클릭했을 때 실제로 드로어가 닫히고 해당 섹션으로 스크롤되는지는
  시각적으로 확인하지 못했다.**
- **6장 `.myth` 표.** §1-4에서 정적 위험을 확인하고 방어적으로 고쳤지만, 375px 등 실제
  뷰포트에서 잘림이 사라졌는지는 눈으로 보지 못했다.
- **접근성 포커스 링.** `:focus-visible` 규칙이 `.pick` `.tog` `.term` `.opt` `.ck`
  (동적으로 `tabindex=0` 부여) `a` `button` `input` `[tabindex]`를 전부 포괄하는 것은
  코드로 확인했다. `.tog`에 `aria-pressed`가 클릭 시마다 갱신되는 것도 확인했다. **실제로
  Tab 키만으로 순회했을 때 시각적으로 링이 보이는지는 확인하지 못했다.**
- **`prefers-reduced-motion: reduce`.** 미디어 쿼리가 존재하고 `animation-duration`을
  `0.01ms`로 강제하는 것은 코드로 확인했다. OS 설정을 켠 상태에서 실제로 트랜지션이 죽는지는
  확인하지 못했다.

- **파티션 개수.** IAM ARN 레퍼런스(셋)와 S3 버킷 이름 규칙(넷)이 서로 어긋나서(facts V11),
  본문 다섯 곳 어디에도 파티션 개수를 숫자나 한글 수사로 적지 않는다.
- **서울 리전의 정확한 AZ 개수.** Task 5가 "확인된 값이 없어 이 장의 원칙을 적용"이라 판단해
  넣지 않았다. 이번 검수에서도 숫자를 찾지 못했다.
- **12장의 단가.** 확인된 것은 퍼블릭 IPv4 시간당 $0.005, NAT 게이트웨이 시간당 $0.045 +
  GB당 $0.045, 이 둘뿐이다. 그 외의 금액(EBS 저장 단가, S3 요청 단가, Lambda 실행 단가 등)은
  본문 어디에도 숫자로 등장하지 않는다 — 필요하면 콘솔의 Cost Explorer로 안내한다(`:1242`).
