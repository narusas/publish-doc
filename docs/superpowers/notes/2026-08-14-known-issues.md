## 1. 다른 튜토리얼 3종에 같은 모바일 버그가 있다

**이번 계획 범위 밖이라 손대지 않았다. 별건으로 판단이 필요하다.**

모바일에서 `☰ 목차` 드로어를 열면 그 안의 어떤 것도 누를 수 없다. `#scrim`이
`#sidebar`보다 위에 있어서, 탭하면 항목이 눌리는 대신 드로어가 닫힌다.

| 파일 | `#sidebar` | `#scrim` | 상태 |
|---|---|---|---|
| `aws_network_security.html` | 160 (모바일) | 150 | **수정됨** |

| `https_tutorial.html` | 50 | 60 | 버그 있음 |

수정 방법은 `aws_network_security.html`의 `@media(max-width:980px)` 블록 참고 —
그 안에서만 `#sidebar`의 `z-index`를 스크림 위로 올렸다. 데스크톱 레이어링은 건드리지 않는다.

함께 고칠 것: TOC 링크 클릭 핸들러가 `sidebar.open`만 지우고 `scrim.open`은 남겨 두면,
내비게이션 후에도 화면을 덮는 오버레이가 남는다. 첫 버그에 가려져 있던 문제다.

## 2. `oauth2_tutorial.html`이 외부 폰트를 불러온다

## 3. 검사기가 잡는 기존 파일의 결함

`python3 tools/check_tutorial.py *.html`로 재현된다. 전부 이번 작업 이전부터 있던 것이다.

- `https_tutorial.html` — `id="tooltip"` 실제 중복, meta description 없음
- `network_basics.html` — 죽은 앵커 `#appendix-encoding`
- `rbac_tutorial.html` — meta description 없음
- `oauth2_tutorial.html` — 위 폰트 문제 + meta description 없음

  이건 파일의 결함이 아니라 검사기가 새 문서용으로 정한 관례의 한계다.

## 4. `aws_network_security.html`에 남긴 것

- **사장된 CSS 약 12KB (전체 35KB 중 34%)** — `iam_tutorial.html`에서 뼈대를 복제할 때
  딸려 온 IAM 전용 컴포넌트(`.ar-*` `.tag-*` `.ladder` `.esc-*` 등). 사용처가 0이지만
  게시 직전에 걷어내는 건 회귀 위험 대비 이득이 없다고 판단했다. `.ev-*`는 관문 파이프라인
  주제와 맞아 재사용 여지가 있다.
- **`.pick` 버튼 88개에 `aria-pressed` 없음** — 토글이 아니라 라디오형 선택이라 치명적이지
  않지만, 접근성을 더 다듬는다면 첫 후보다.
- **체크리스트 점수가 "9 / 8"처럼 나올 수 있음** — 저장된 키 목록과 현재 항목 수가 어긋나면
  발생한다. 항목을 추가·삭제하거나 `data-k`를 바꾸면 재현된다.
- **퀴즈 id `q-outside`가 섹션 id `attach`와 어긋남** — 1장을 재작성하며 섹션 이름은 바꾸고
  퀴즈 id는 유지했다. 기존 독자의 진행률 기록을 보존하려는 의도였다. 바꾸려면 위의
  체크리스트 문제와 같은 종류의 마이그레이션이 필요하다.

## 5. 사실 검증의 교훈

이 문서를 만들며 사실 오류 **네 건**이 리뷰에서 걸렸고, **전부 계획 문서에서 나왔다** —
구현 과정에서 생긴 게 아니라 기억으로 초안을 쓴 데서 나왔다.

1. Flow Logs가 NACL 차단을 기록하지 않는다 (틀림 — SG와 똑같이 `REJECT`를 남긴다)
2. Flow Logs 집계 주기 5분 (틀림 — 10분 기본 / 1분)
3. `local` 라우트의 타깃을 바꿀 수 없다 (틀림 — 바꿀 수 있고, 그게 동서 검사의 원리다)
4. Transit Gateway를 쓰면 각 VPC가 라우팅 테이블을 갖지 않는다 (틀림 — 여전히 필요하다)

반대 방향의 실수도 한 번 있었다. 구현자가 실재하는 규칙명 `SQLi_BODY`를 "지어낸 것 같다"며
일반 표현으로 뭉갠 일이다. **올바른 처리는 "불확실하면 완화"가 아니라 "확인한 뒤 유지하거나
제거"다.** 참인 구체를 뭉개면 독자가 찾아볼 수 있는 유일한 단서를 잃는다.

`docs/superpowers/notes/2026-08-12-aws-facts.md`가 이 문서의 근거 기록이다. 서술을 고칠 때는
그 파일을 먼저 보고, 없는 사실은 확인한 뒤에 쓴다.

# 남겨 둔 것들 — 2026-08-15 (`auth_basics.html`)

웹 애플리케이션 인증 기초 문서를 마치며, 알고도 고치지 않은 것과 범위 밖에서 발견된 것을
기록한다. 최종 검수에서 **게시를 막지 않는다**고 판정된 항목들이다.

## 6. 이 문서에 남긴 것

- **밀도 파형이 2부 이후 고르지 않다.** 7~13장이 일곱 장 연속 5.6k자 이상이고, 최고점인
  13장(약 6.6k)이 독자가 가장 지친 자리에 있다. 1부는 3.1/6.5/3.2/5.3/4.5/6.6으로 잘
  갈마드는데 2부 이후엔 골짜기가 없다. **구조 결정이라 퇴고에서 손대지 않았다** — 13장을
  가르려면 `data-title`·목차·15장 회수표·`#chainPlay`를 함께 건드려야 한다.
- **퀴즈 해설 11개가 `정답 → 오답×3 → 확장`이라는 같은 골격을 공유한다.** 각 장의 "가장 흔한
  오답"이 특정 보기 자리에 오도록 배치돼 있고 해설이 그 자리를 이름으로 가리켜서
  (`B가 이 장에서 가장 흔한 오답입니다`), 순서를 흔들면 문장이 어긋난다. 논리를 건드려야
  바뀌므로 퇴고의 일이 아니라고 판단했다.
- **13장 클로징이 다른 장보다 약하다.** 퇴고 3라운드에서 같은 절의 콜아웃에 이미 있던 미결을
  `.oneline` 끝에 놓아 한 번 세웠지만, 다른 장의 맺음만큼 강하지는 않다. 14장의 반전
  (1~13장이 "우리가 비번을 직접 받는다"는 전제 위에 있었다)을 미리 터뜨리지 않아야 한다는
  제약이 걸려 있다.
- **`#cookieLab`의 `SameSite` 미지정 + 링크 클릭 행**은 실제로 어느 브라우저에서나 쿠키가
  붙는데 배지가 "브라우저마다 다름"으로 뜬다. 설명 문장이 "결과는 같은데 이유가 다른 자리"로
  해소하지만 배지 자체는 폼 POST 행과 시각적으로 같다.
- **11장 퀴즈 해설의 "예외가 있으며"가 현재 시제다.** `SameSite`의 2분 예외는 Chrome이
  없애는 중이라, 실제로 제거된 시점의 독자에게는 문면상 어색해진다. 같은 절의 신화 상자가
  "임시/제거 예정"을 이미 못 박아 오해를 유발할 정도는 아니다.
- **`#lbSim`(7장)의 색 축이 다른 데모와 다르다.** 여기서는 로그아웃이 빨강인데, 그 로그아웃은
  아무도 시키지 않은 사고이고 `#tradeoff`(9장)의 차단은 시켜서 일어난 일이라 논리적으로는
  어긋나지 않는다. 머리말에 그 구분을 적어 두었지만 **읽어야 통하는 해법**이라, 데모를
  건너뛰고 표만 훑는 독자에게는 모순이 남는다. 색을 바꾸면 7장 논지와 데모 내부 축이
  함께 무너져 트레이드오프 끝에 그대로 두었다.

## 7. 부록 B는 1차 출처 검증을 받지 않았다

부록 B(Express·Django·Rails 대응표)만 이 문서에서 유일하게 **1차 공식 문서 원문 대조를
거치지 않았다.** 근거 파일에 세 프레임워크 항목이 없어서, 구현자가 **이름만 적고 동작 설명을
일절 넣지 않았고** 문서 안에도 "맞춰 놓은 것은 이름까지"라고 명시했다.

리뷰어가 7행 × 3열을 웹 검색으로 교차 확인해 **전부 정확**했지만, 그 검증은 이 문서의 나머지가
받은 수준(공식 문서 원문 인용)에는 못 미친다. **정식으로 올리려면 각 프레임워크 공식 문서를
원문으로 별도 확인해야 한다.**

## 8. 검사기에 대해 알아낸 것

- **`tools/check_dead_css.py`를 이번에 만들었다.** 골격을 복제할 때 딸려 오는 사장 CSS를
  막는 것이 목적이다. 만든 근거는 실측이었다 — `aws_network_security.html`은 CSS 클래스
  **226개를 정의하고 95개만 쓴다(58%가 사장)**. known-issues §4가 적어 둔 "약 34%"보다 크다.
- 작업 중 검사기 결함 셋을 찾아 고쳤다: ① CSS 주석을 건너뛰지 않아 주석 안의 `.무엇`을
  클래스 정의로 오인 (Python 3의 `\w`가 한글까지 먹는다) ② `element.className = '...'`와
  `setAttribute('class', ...)`를 사용으로 인식하지 못함 ③ Prism 압축 소스의 문자열 조각이
  역방향 검사에 오탐으로 잡힘.
- ①은 **자기 커밋에서 필요성이 증명됐다.** 그 수정을 넣은 태스크가 새로 쓴 CSS 주석 둘이
  옛 검사기에서는 오탐으로 잡혀 차단형 검사를 FAIL시켰을 것이다.
- **남은 한계**: 검사기가 `$('.foo')` / `$$('.foo')` 선택자 인자도 "사용"으로 센다. 선택자만
  배선하고 실제 마크업·CSS를 빠뜨려도 forward 검사가 못 잡는다.

## 10. 사실 검증에서 얻은 것 — §5의 후속

`aws_network_security.html` 때 얻은 교훈("사실 오류 네 건이 전부 계획 문서에서 나왔다")에
대응해, 이번에는 **구현 계획을 쓰기 전에 사실 여덟 건을 공식 문서로 확인**하고
`docs/superpowers/notes/2026-08-14-auth-facts.md`에 근거와 인용을 남겼다. 그 결과:

- 작업 중 사실 문제가 **아홉 번** 잡혔고, 그중 **여섯 번은 구현자가 스스로 "근거가 없어
  쓰지 않고 남긴다"고 표시한 자리**였다. 리드가 그 자리만 확인해서 근거를 만들면 됐다.
- **그런데 한 번은 근거 파일 자체가 틀렸다.** `requireExplicitSave`의 방향을 리드가 반대로
  적었고, 구현자는 "확인됨"으로 표시된 그것을 신뢰해 그대로 옮겼다. 리뷰어가 1차 출처를
  직접 받아 잡아냈다. **"이 항목은 낡은 블로그가 특히 자주 틀린다"고 경고해 놓은 바로 그
  자리에서 틀렸다.**
- 재확인 중에 요약 한 쪽이 **자기가 인용한 문장과 모순되는 결론**을 냈다. 인용문이 맞고
  요약이 틀렸다. → **인용문과 요약이 어긋나면 인용문을 믿는다.**

**다음 문서를 위한 규칙 두 개:**
1. 근거 파일이 "확인됨"이어도, **표·인용문과 그 아래 요약 문장이 어긋나는지** 옮겨 쓸 때 한 번
   대조한다. 이번에 구현자가 인용문은 그대로 옮기면서 요약 문장은 검증 없이 옮겼다.
2. 구현자가 **"근거가 없어 쓰지 않았다"고 보고하는 것을 장려한다.** 이번 아홉 건 중 여섯이
   그렇게 잡혔다. 완화해서 뭉개는 것보다 비워 두고 보고하는 쪽이 훨씬 싸다.
