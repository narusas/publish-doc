# AWS 네트워크 보안 튜토리얼 — 설계 문서

- 날짜: 2026-08-12
- 산출물: `aws_network_security.html` (신규), `index.html` (카드 추가)
- 시리즈: 인터랙티브 개발 튜토리얼 모음 (현재 6번째 문서)

## 1. 왜 만드는가

시리즈 6종을 전수 검사한 결과, `Security Group` / `NACL` / `VPC` / `WAF` 는 어느 문서에도
등장하지 않는다. 인접한 두 문서는 각각 다른 층에서 멈춰 있다.

- `network_basics.html` — 방화벽을 다루지만 **리눅스 netfilter/iptables 관점**이다. 벤더 중립이
  이 문서의 정체성이라 AWS 고유명사를 넣으면 축이 무너진다.
- `iam_tutorial.html` — 클라우드 통제를 다루지만 **API 호출 층**에서 끝난다. 패킷은 다루지 않는다.

즉 **"패킷 층의 클라우드 관문"이 시리즈의 빈 칸**이고, 이 문서가 그 자리를 채운다.
동시에 두 문서를 잇는 다리가 된다 — netfilter가 왜 클라우드에서 안 통하는지(1장),
네트워크 경계와 신원 경계가 어디서 곱해지는지(11장).

## 2. 척추

> **"SG를 0.0.0.0/0으로 다 열었는데 왜 timeout인가."**

이 한 문장이 문서 전체를 끈다. 범인이 최소 여섯이고, 하나씩 소거하는 과정이 곧 관문의 목록이 된다.

1. 라우팅 테이블에 IGW가 없다
2. 인스턴스에 퍼블릭 IP가 없다
3. NACL이 응답용 ephemeral 포트를 막았다
4. OS 방화벽이 막았다
5. 앱이 `127.0.0.1`에만 바인딩했다
6. 애초에 다른 서브넷이다

**전개 방식**: 증상 추적형. 계층 순서도, 시간 순서도 아니고 **범인을 소거하는 순서**로 간다.
`network_basics.html` 의 "문제의 순서" 전개를 계승한다.

## 3. 무대

`iam_tutorial.html` 의 "나루 클라우드"를 그대로 이어받는다. prod 계정의 3-tier 주문 서비스
(ALB → EC2 앱 → RDS)를 문서 전체에서 재사용하고, 김주임·박팀장·이보안 페르소나도 유지한다.
시리즈 연속성이 공짜로 따라오고, 독자가 새 세계관을 학습할 필요가 없다.

## 4. 독자와 선수 지식

- 대상: 주니어~중급 개발자. AWS 콘솔은 만져 봤지만 VPC를 설계해 본 적은 없는 사람.
- 전제하지 않는 것: VPC 구조(CIDR·서브넷·AZ·라우팅 테이블). **2장에서 발판으로 깔고 간다.**
  단, 본론이 아니라 발판임을 명시하고 건너뛸 수 있게 만든다.
- 전제하는 것: TCP 3-way handshake, 포트, IP 라우팅의 개념. `network_basics.html` 수준.
- 난이도 표시: 제목 옆 🟢 필수 / 🔵 심화 (`iam_tutorial.html` 의 `.lvl` 패턴).

## 5. 구성 — 15장 + 부록 2

### 1부 · 관문의 순서 (1~7장)

#### Hero · "다 열었는데 왜 timeout인가"
30초 자가진단(`.diag`) → 무대 소개 → 지도(`.map-grid`) → 읽는 법.

#### 1장 · 🧱 클라우드의 방화벽은 서버 안에 없다 🟢
- `iptables`는 커널 안, SG는 ENI 밖(하이퍼바이저 층).
- 결정타: **SG가 버린 패킷은 `tcpdump`에 잡히지 않는다.** OS는 그 패킷의 존재조차 모른다.
- 따라서 "서버에 들어가서 확인"이라는 습관이 통하지 않는다. netfilter를 아는 사람일수록 헛발질한다.
- 통제가 붙는 자리 미리보기(엣지·VPC·서브넷·ENI·LB·앱).
- **데모**: 같은 차단을 iptables로 / SG로 걸었을 때 서버에서 관측되는 것 비교.

#### 2장 · 🗺️ VPC 기초 — 발판 🟢 (건너뛰기 가능)
- CIDR · 서브넷은 AZ에 갇힌다 · 진짜 주체는 인스턴스가 아니라 **ENI**.
- 오해 격파: **"퍼블릭 서브넷"이라는 속성은 존재하지 않는다.** 라우팅 테이블에 IGW가 걸렸느냐일 뿐.
- **데모**: VPC 지도(서브넷·ENI·라우팅 테이블 클릭), CIDR 분할기.

#### 3장 · 🧭 경로가 곧 통제다 🟢
- 라우팅 테이블 = longest prefix match.
- IGW는 NAT이 아니다 — 1:1 변환이며 퍼블릭 IP가 필요하다.
- NAT GW가 단방향인 이유.
- **회수 예고**: 여기서 정한 라우팅이 9장 Network Firewall 삽입의 전부가 된다.
- **데모**: 라우팅 시뮬레이터 — 목적지 IP를 넣으면 어느 타깃으로 가는지.

#### 4장 · 🛡️ Security Group — 상태 유지 검문소 🟢
- 인스턴스가 아니라 **ENI에 붙는다**.
- allow만 있고 deny가 없다.
- 규칙 사이에 순서가 없다 — 전부 OR.
- 상태 유지라 응답은 자동 통과.
- 아웃바운드 기본은 전체 허용.
- 여러 개를 붙이면 합집합.
- **데모**: SG 규칙 편집기 + 패킷 던지기.

#### 5장 · 🧊 NACL — 무상태 검문소 🟢
- 서브넷에 붙는다 · 번호 순서 · **deny를 쓸 수 있다** · 첫 매치 승.
- 무상태라 응답도 검사받는다 → **ephemeral 포트(1024–65535)를 열어야 한다**는 함정.
- 기본 NACL은 전부 허용이라 조용하다가, 커스텀 NACL을 만드는 순간 터진다.
- **데모**: SG vs NACL 나란히 — 요청과 응답을 양쪽에 통과시켜 함정 재현.

#### 6장 · ⚖️ 관문의 순서 🟢 **[클라이맥스]**
- 인바운드: `IGW → 라우팅 → NACL(in) → SG(in) → OS → 앱`
- 응답: `SG(상태로 자동 통과) → NACL(out) ← 여기서 죽는다 → 라우팅 → IGW`
- 시나리오별로 체인이 어떻게 달라지는지.
- **데모(핵심)**: 관문 체인 시뮬레이터.
  - 시나리오: 인터넷→웹 / 웹→RDS / 앱→S3 / 앱→인터넷
  - 고장 주입: 라우팅 없음 · NACL 아웃바운드 차단 · SG 방향 오류 · 퍼블릭 IP 없음 등
  - 출력: 어느 관문에서 죽는지 애니메이션 + **그때 관측되는 증상**

#### 7장 · 🔍 어디서 막혔는지 알아내는 법 🟢
- `timeout` vs `connection refused` — `network_basics.html` 의 RST 이야기 회수.
- VPC Flow Logs 읽기.
- **로그의 비대칭**이 핵심이다. Flow Logs는 ENI 단위이므로, SG가 막으면 `REJECT`가 남지만
  NACL이 인바운드를 막으면 ENI에 닿지도 않아 **아무 줄도 남지 않는다.**
  "로그가 없다"가 그 자체로 단서가 되는 구조. (→ §8 검증 항목 V1)
- Reachability Analyzer.
- **데모**: Flow Log 한 줄 해부기 + 증상→범인 판별 트리.

### 2부 · 연동 구성 (8~15장)

#### 8장 · 🔗 IP가 아니라 신원으로 — SG 참조 🟢
- SG 규칙의 source 자리에 CIDR 대신 **다른 SG**를 넣을 수 있다.
- 오토스케일링으로 IP가 매분 바뀌는 환경에서 CIDR 기반 규칙은 애초에 성립하지 않는다.
- 프레이밍: **SG는 방화벽 규칙이 아니라 라벨이다.**
- `alb-sg` → `app-sg` → `rds-sg` 체인으로 IP를 한 번도 쓰지 않고 3-tier를 잠근다.
- **데모**: SG 참조 체인 빌더 — 3-tier 연결 + 잘못된 연결이 만드는 구멍 확인.

#### 9장 · 🚧 AWS Network Firewall — 붙이는 게 아니라 경유시키는 것 🔵
- SG·NACL은 리소스에 **붙지만**, 이것은 트래픽을 **지나가게 만들어야** 한다.
- 3장의 라우팅이 통째로 회수된다. 방화벽 엔드포인트를 next hop으로 넣지 않으면
  규칙을 아무리 써도 트래픽이 근처에도 가지 않는다.
- Suricata 규칙 · TLS SNI 기반 도메인 필터링(SG로는 불가능한 것) · 중앙 인스펙션 VPC + TGW.
- **데모**: 삽입 라우팅 실습 — 라우팅 테이블을 어떻게 고쳐야 트래픽이 방화벽을 지나는지.

#### 10장 · 🌊 WAF — 연결된 뒤에 보는 관문 🔵
- WAF는 SG를 대체하지 못한다. **축이 다르다** — SG는 연결 자체를 막고, WAF는 이미 맺어진
  연결 위의 HTTP를 읽는다. SQLi나 요청 본문은 SG가 볼 수 없고, 포트는 WAF가 볼 수 없다.
- Managed rule · rate limit.
- **우회 문제**: CloudFront에 WAF를 걸어도 ALB 주소를 직접 때리면 그만이다.
  답은 ALB의 SG를 CloudFront managed prefix list로 좁히는 것 — 8장이 다시 회수된다. (→ V3)
- **데모**: WAF 규칙 테스트기 + 우회 경로 시연.

#### 11장 · 🔒 인터넷을 거치지 않고 만나기 — VPC Endpoint 🟢
- Gateway형(라우팅 테이블 항목으로 나타남) vs Interface형(**ENI가 생기므로 SG가 붙는다** — 4장 회수). (→ V5)
- Endpoint Policy.
- **IAM 튜토리얼과 만나는 지점**: `aws:SourceVpce` / `aws:SourceVpc` 조건키로
  **네트워크 경계와 신원 경계가 곱해진다.** "이 역할이, 이 VPC 안에서만"이 처음 가능해진다.
  두 문서를 다 읽은 사람에게만 열리는 문.
- **데모**: Endpoint 정책 × IAM 정책 결합 판정기.

#### 12장 · 🕸️ VPC끼리 잇기 🔵
- Peering은 **전이되지 않는다** — A–B와 B–C가 있어도 A–C는 없다.
- CIDR이 겹치면 방법이 없다.
- TGW는 허브.
- 리전 내 peering이면 SG 참조가 경계를 넘는다. (→ V2)

#### 13장 · 🏗️ 전부 합친 3-tier 레퍼런스 🟢
- 지금까지의 통제를 그림 하나에 얹는다.
- **데모**: 종합 여정 재생기 — 요청 하나의 전체 여정.

#### 14장 · 🧨 함정과 설계 원칙 🟢
- `0.0.0.0/0`으로 열린 22번 포트.
- 기본 SG를 그냥 쓰기.
- NACL을 보안 도구로 오용하기.
- **아웃바운드 무제한** — 데이터 유출 경로.
- SSH 대신 SSM Session Manager.
- Terraform으로 SG를 관리할 때의 규칙 폭발.

#### 15장 · 🏁 마무리 — 내 VPC에는 몇 개가 열려 있나
- 체크리스트(`.ckl`) + Hero 자가진단 회수.
