# 튜토리얼 → 발표 자료 변환 — 설계 문서

- 날짜: 2026-08-20
- 산출물(파일럿): `oauth2_slides.html` (신규), `tools/check_slides.py` (신규)
- 범위: 인터랙티브 튜토리얼 8편 전부를 50~60분 발표용 덱으로. **oauth2를 파일럿으로 먼저 만들고, 통과하면 나머지 7편에 같은 규칙을 적용한다.**

## 1. 왜 만드는가

튜토리얼 8편은 **혼자 읽는 물건**으로 설계돼 있다. 사이드바 목차, 스크롤 진행률, 마우스 오버 용어
설명, 자기 채점 퀴즈 — 전부 독자가 자기 속도로 오가는 것을 전제한다.

발표는 반대다. **속도를 발표자가 쥐고, 청중은 되감을 수 없다.** 같은 내용이라도 한 화면에 담기는
양, 문장의 길이, 되짚는 횟수가 달라야 한다. 그래서 튜토리얼을 화면에 띄워 놓고 스크롤하는 방식은
발표가 되지 않는다. 별도의 산출물이 필요하다.

동시에 밑바닥부터 쓸 필요도 없다. 이 시리즈의 튜토리얼에는 **이미 발표용 비트가 들어 있다**
(3절 참조). 이 작업의 본질은 창작이 아니라 **재배열**이다.

## 2. 이 변환의 중심 문제 — 시간

oauth2 튜토리얼 본문(마크업 제거)은 23,300자다. 한국어 발표 속도 330자/분으로 그대로 읽으면
**70분**이다. 목표는 50~60분이다.

여기서 나오는 결론이 이 설계 전체를 지배한다.

> **슬라이드는 본문의 요약이 아니다. 본문을 무대용으로 재구성한 다른 문서다.**

본문을 잘라 붙이는 방식으로는 70분이 55분이 되지 않는다. 문장을 줄이면 논지가 끊기고, 장을
통째로 빼면 사슬이 끊긴다. 대신 **말로 할 것(대본)과 화면에 남길 것(슬라이드)을 분리**하고,
장의 취사선택을 명시적으로 한다.

### 시간 목표: 대본 기준 52분

50~60분 요구에 대해 **대본은 52분**으로 쓴다. 사내 스터디는 중간 질문이 반드시 나오고 라이브
데모는 언제나 예상보다 늘어진다. 52분 대본 + 질문·호흡 5~8분 = 실제 57~60분. 대본을 55분으로
채우면 현장에서 65분이 된다.

## 3. 재사용할 자산 — 이미 있는 것

`oauth2_tutorial.html`(2,548줄, 단일 `<style>` + 단일 `<script>`)에 들어 있는 것:

| 자산 | 수량 | 발표에서의 가치 |
|---|---|---|
| 애니메이션 SVG 다이어그램 `.dia` | 10개 / 총 66프레임 | **프레임마다 구어체 나레이션과 체류시간(`h:2600`)이 이미 박혀 있다** |
| 시퀀스 플레이어 `createSequence` | 5개 (메인 16단계 포함) | 단계별 HTTP 원문 + "무슨 일 / 왜 중요 / 초보 주의" 노트 완비 |
| 라이브 데모 | 11개 | PKCE SHA-256, JWT 서명 위조·검증, state 위조, scope 부족 403 — WebCrypto 실연 |
| 퀴즈 | 13개 | 세미나 호흡 조절용 |

핵심은 `wireDia`의 프레임 캡션이다. 이미 **말로 하는 문장**이고 **체류시간까지 있다.** 사실상
완성된 발표 비트다.

## 4. 청중과 자리

- **대상**: 사내 주니어 대상 스터디·세미나. 튜토리얼이 상정한 독자와 같은 층.
- **전제하는 것**: HTTP 요청/응답의 모양. 쿠키·세션으로 로그인을 붙여 본 경험. `auth_basics.html` 수준.
- **전제하지 않는 것**: OAuth의 어떤 것도. 토큰·scope·리다이렉트의 정의도.
- **자리의 성격**: 질문이 오간다. 중간에 멈추고 되짚을 수 있어야 하고, 안 나온 질문에 시간을 쓰면 안 된다.

## 5. 접근 방식 — 셋 중에서

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| A | **추출·재조립** — 새 단일 파일에 자산 복사, 슬라이드는 무대용으로 새로 작성 | 발표 호흡에 맞춘 완전한 통제. 덱이 단독 완결 | 다이어그램 복제. 원본 수정 시 동기화 필요 |
| B | 튜토리얼에 `?present=1` 발표 모드 오버레이 | 복제 없음. 단일 출처 | **산문 구조는 CSS만으로 슬라이드가 되지 않는다.** 취사선택·재배열이 원본 순서와 충돌 |
| C | 매니페스트 + 빌더(`build_slides.py`)로 생성 | 8편 반복에 가장 강함 | 파일럿 하나 만드는 초기 비용이 큼. 스파이크 단계에 과함 |

### 결정: A로 만들되 C의 이음매를 미리 긋는다

oauth2는 손으로 만든다 — 포맷이 맞는지가 아직 검증되지 않았다. 다만 덱의 **공용부와 콘텐츠부를
파일 안에서 마커 주석으로 확실히 가른다**(9절). 파일럿이 통과하면 공용부를 그대로 들어내
`tools/build_slides.py`로 옮기고, 나머지 7편은 매니페스트와 대본만 쓴다. 통과하지 못하면 버리는
비용도 A가 가장 싸다.

## 7. 화면 구조

### 슬라이드 규격: 1280×720 고정 좌표계

튜토리얼의 SVG는 `width:100%` 반응형이라 화면 크기에 따라 글자가 커졌다 작아진다. 발표에선
그러면 안 된다 — **뒷자리에서 읽히는 최소 글자 크기가 화면마다 달라지기 때문이다.**

슬라이드는 1280×720 고정 좌표계로 그리고 뷰포트에 맞춰 `transform: scale()`로 통째 확대한다.
어떤 프로젝터에 꽂아도 레이아웃과 상대 글자 크기가 같다.

**글자 크기 하한(1280 기준)**: 본문 24px, 코드 20px. 이 둘만 강제한다(10절).

강조 문장에는 하한이 없다. 초안에는 "강조 문장 40px 이상"이 적혀 있었지만 만들지
않았고, 만들 수도 없었다 — 파일럿의 `h2` 는 44px 이 기본인데 제목이 긴 25장은 34px 로
내려간다(1280×720 안에서 두 줄이 넘어가면 본문 자리를 먹는다). 40px 하한을 강제했다면
**파일럿 자신이 25장에서 실패한다.** '강조 문장'을 마크업으로 구별하지도 않으므로
검사기가 무엇을 재야 하는지도 정의되지 않았다.

실제로 강제하는 곳은 두 군데다. `tools/check_slides.py` 의 `check_font_floor` 는
인라인 `style` 만 보고(이 덱에서는 0개를 잡는다), `tools/test_deck_behavior.py` 의
`test_every_visible_text_is_at_or_above_the_font_floor` 가 브라우저로 computed 값을
재서 24/20 을 강제한다. CSS 규칙 쪽을 정규식으로 세는 길은 닫혀 있다 — 이식해 온
`ASSET:CSS` 값을 `DECK:STAGE:CSS` 가 덮어쓰는 구조라 캐스케이드를 다시 구현해야 한다.
그래서 그 브라우저 테스트는 chromium 이 없으면 skip 하지 않고 **실패한다.**
하한 아래에 두는 예외는 덱의 `DECK:STAGE:CSS` 「활자 하한」 주석 안
`==== 예외 목록 시작/끝 ====` 블록에 `[셀렉터] 바닥 Npx — 근거` 로 적고,
예외에도 저마다 바닥이 있다.

### 화면 두 개

프로젝터 창과 발표자 창. 발표자 창은 `window.open`으로 띄운 **자식 창의 DOM을 메인 창이 직접
갱신**한다. BroadcastChannel도 localStorage도 쓰지 않으므로 `file://`로 열어도 동작한다 — 이 시리즈
문서는 로컬에서 여는 일이 많아 이 점이 중요하다. 팝업이 차단되면 토스트로 알리고 한 창짜리 노트
서랍(`S`)으로 물러선다.

발표자 창에 띄우는 것: 경과/예정 시각과 차이, 현재 슬라이드 제목, **다음** 슬라이드 제목, 현재
슬라이드 대본.

### 키보드 — 오른쪽 화살표 하나로 발표가 굴러가게

이 덱에서 가장 중요한 조작 결정이다.

`.dia`는 프레임이 6~7개씩 있고 `createSequence`는 단계가 16개까지 간다. **슬라이드 넘김과 프레임
전진에 다른 키를 배정하면 발표자가 발표 중에 "지금 어느 키를 눌러야 하지"를 생각해야 한다.**

그래서 `→`는 **"다음 비트"** 하나로 통일한다 — 현재 슬라이드에 남은 프레임이 있으면 프레임을
전진시키고, 다 소진했으면 다음 슬라이드로 간다.

| 키 | 동작 |
|---|---|
| `→` `Space` | 다음 비트 (프레임 → 다 쓰면 다음 슬라이드) |
| `←` | 이전 비트 |
| `↓` `↑` | 슬라이드 통째로 건너뛰기 (프레임 무시) |
| `P` | 발표자 창 |
| `S` | 노트 서랍 (한 창 대체 수단) |
| `O` | 개요 그리드 — 썸네일 클릭 점프 |
| `A` | 부록 첫 장 |
| `T` | 타이머 시작·정지 |
| `F` | 전체화면 |
| `숫자` `Enter` | 해당 번호로 점프 |

### 시간 계측

슬라이드의 예정 시간은 **대본 글자 수 ÷ 5.5자/초**(= 330자/분)로 그때그때 계산한다.
초안에는 "슬라이드마다 `data-sec`을 박는다"가 적혀 있었지만 **박지 않기로 했고, 덱에
`data-sec` 은 하나도 없다.** 대본과 숫자가 두 곳에 따로 있으면 대본을 고칠 때마다
숫자를 같이 고쳐야 하고, 안 고쳐도 아무 표시가 없다. 지금은 `Deck.secOf(id)` 와
`check_slides.py` 의 `seconds()` 가 같은 대본을 읽어 각자 센다.

값을 따로 안 박는 대신 **상수는 두 곳에 있다.** `SPEED`·`SLIDE_MIN`·`SLIDE_MAX` 가
덱과 검사기 양쪽에 있고, `test_the_deck_and_the_checker_share_their_constants` 가
대조한다. (반올림 규칙까지 맞춘 것은 아니다 — 두 구현이 67장 중 9장에서 1초씩
갈린다. 알려진 이슈 노트 2-b 참고.)

상단 진행 바는 두 줄 — 위는 슬라이드 위치, 아래는 **예정 대비 실제**(앞서면 초록,
늦으면 주황). 두 막대의 분모는 **본편**이다. 부록은 발표하지 않는 장이라 예정 시간에
들어가면 안 된다.

효과는 리허설 전에 나온다. 대본을 다 쓰면 합계가 즉시 나오므로 **52분에서 벗어나면 그 자리에서
대본을 깎는다.** 발표 당일에 알게 되는 일이 없다.

### 테마

다크를 유지한다. SVG 다이어그램이 다크 전제로 그려져 있어(`fill:var(--bg)`, 텍스트 `#fff`) 밝은
테마로 뒤집으려면 SVG 색 변수를 전부 재정의해야 하고, 그것은 파일럿 범위를 넘는다.

대신 **무대용 변수 오버라이드를 한 겹 얹는다** — `--text-dim`·`--text-mut`를 밝은 쪽으로 올리고
배경을 더 어둡게 해 명도 대비를 한 단계 키운다. 회의실 조명이 밝아도 뒷자리에서 읽히도록.

### 자동재생 다이어그램의 처리

튜토리얼의 `wireDia`는 `setTimeout` 자동재생이다. 발표에서는 **자동재생을 기본으로 끄고 키 입력으로
전진**한다. 프레임의 `h` 값은 지우지 않고 남겨 시간 추정에만 쓴다. `createSequence`는 이미 수동
next 버튼 기반이므로 키에 그대로 연결한다.

예외는 #5와 #15의 `mainSeq`다. 여기서는 자동재생을 쓴다 — 16단계를 키로 넘기면 3분 30초 안에
들어오지 않고, 이 두 자리의 목적은 세부가 아니라 **흐름의 윤곽**이기 때문이다.

## 8. 대본

슬라이드 안이 아니라 파일 하단 데이터 블록에 모은다. **JS 객체가 아니라 JSON 이고,
키는 슬라이드 id 그대로다**(`s00`..`s52` · `a00`..`a13`).

```html
<script type="application/json" id="deck-script">
{
  "s30": [
    "인가 요청에 실려 나가는 것은 자물쇠뿐입니다.",
    "공격자가 이걸 봐도, 해시는 되돌릴 수 없어요."
  ]
}
</script>
```

초안에는 `const SCRIPT = { 's09-pkce-lock': [...] }` 로 적혀 있었지만 그렇게 짓지
않았다. 두 가지가 달라졌다.

- **JS 가 아니라 JSON.** 표준 라이브러리만 쓰는 검사기가 `json.loads` 로 그대로 읽어야
  한다. JS 객체 리터럴이면 검사기가 파서를 하나 더 들고 있어야 하고, 그러면 덱이 읽는
  것과 검사기가 읽는 것이 다른 문법이 된다.
- **키는 슬라이드 id 와 글자까지 같다.** 별도의 이름(`s09-pkce-lock`)을 쓰면 대본과
  슬라이드를 잇는 표가 하나 더 생기고, 그 표가 어긋나도 화면에는 아무 표시가 없다.
  같은 문자열이므로 `check_script_present` 가 양방향으로 대조한다 — 대본 없는 슬라이드와
  슬라이드 없는 대본을 둘 다 잡는다.

`<script type="application/json">` 이라 브라우저가 실행하지 않고, `id` 하나로 덱과
검사기가 같은 자리를 가리킨다. 대본 안에 `</script` 가 들어가면 HTML 파서가 거기서
대본을 끊으므로(XSS 를 다루는 장에서 실제로 나올 수 있다) `check_script_terminator`
가 그것만 따로 본다.

53장에 흩어 놓지 않는 이유 셋:

1. **글자 수 합계를 한 번에 재야** 52분을 맞출 수 있다.
2. 시간이 안 맞을 때 **깎을 곳을 한 화면에서 고를 수 있다.**
3. `tts_script.json` 파이프라인이 문단 배열을 먹으므로 **같은 모양으로 맞춰 두면 리허설 음성을
   그대로 뽑을 수 있다.**

대본은 **그대로 읽으면 발표가 되는 완성된 문장**으로 쓴다. 불릿이 아니다. 그래야 글자 수로 시간이
계산되고, 다른 사람이 대신 발표할 수 있다.

## 9. 파일 구조

```
oauth2_slides.html
├─ <style>
│   ├─ /* ==== DECK:CORE:CSS ==== */    슬라이드 엔진·노트·타이머·개요 그리드
│   ├─ /* ==== DECK:STAGE:CSS ==== */   무대용 팔레트 오버라이드
│   └─ /* ==== ASSET:CSS ← oauth2_tutorial.html ==== */   .dia / .seq / 데모 CSS
├─ <body>
│   ├─ <!-- ==== DECK:CHROME ==== -->   진행바 2줄·HUD·노트 서랍·개요 그리드·토스트
│   ├─ <!-- ==== SLIDES ==== -->        본편 53장 + 부록 14장
│   └─ <!-- ==== DECK:CHROME ==== -->   (SLIDES 뒤에 오는 두 번째 조각)
├─ <script type="application/json" id="deck-script">   슬라이드별 대본
└─ <script>
    ├─ /* ==== DECK:CORE:JS ==== */     내비게이션·비트 시스템·타이머·발표자 창
    └─ /* ==== ASSET:JS ← oauth2_tutorial.html ==== */    wireDia·createSequence·데모
```

**대본에는 마커가 없다.** 초안에는 `/* ==== DECK:SCRIPT ==== */` 가 적혀 있었지만
그런 마커는 만들지 않았다 — 대본은 `<script type="application/json" id="deck-script">`
안의 JSON 한 덩어리이고, `id` 자체가 이미 그 자리를 가리킨다. 주석 마커를 JSON 안에
넣을 수도 없다. 검사기와 덱이 둘 다 이 `id` 로 찾는다.

**`DECK:CHROME` 은 마커가 둘이다.** `SLIDES` 가 `#stage` 안에 들어앉아 크롬을 둘로
가르기 때문이다. 뽑을 때는 두 조각을 순서대로 이어 붙이고 그 사이에 `SLIDES` 를 끼운다.
이 블록이 마커를 갖는 이유는 `DECK:CORE:CSS` 가 꾸미고 `DECK:CORE:JS` 가 **하드
의존**하는 열한 개의 id 가 여기 있기 때문이다(`viewport`·`stage`·`bars`·`barPos`·
`barTime`·`hud`·`clock`·`counter`·`notes`·`overview`·`toast`). `paint()` 는 이 중 첫
하나만 없어도 그 자리에서 던진다 — 크롬 없이 CORE 두 블록만 뽑으면 붙을 DOM 이 하나도
없는 CSS 와 JS 가 나온다. `test_the_deck_chrome_lives_inside_its_own_marker` 와
`test_every_id_the_core_js_reaches_for_is_in_the_chrome_block` 이 그 짝을 지킨다.

`DECK:CORE:*` 와 `DECK:CHROME` 은 **문서 내용과 무관하다.** 파일럿 통과 후 이 블록들이
`build_slides.py`의 템플릿이 된다. `ASSET:*` 블록에는 **원본 파일과 줄 번호를 주석으로
박는다** — 튜토리얼이 바뀌었을 때 어디를 다시 봐야 하는지 알 수 있게.

산출물 목록:

| 파일 | 상태 |
|---|---|
| `oauth2_slides.html` | 신규 — 단일 자체완결 파일 |
| `tools/check_slides.py` | 신규 — 덱 검사기 |
| `index.html` | **파일럿 통과 후에** 손댄다. 지금 카드를 추가하면 검증 안 된 포맷이 허브에 걸린다 |

## 10. 파일럿 통과 기준

"포맷이 맞는가"를 감으로 판정하지 않기 위해 세 층으로 검사한다.

### 기계 검사 — `tools/check_slides.py`

- 대본 없는 슬라이드가 있는가
- 대본 합계가 **52분 ±3분** 안인가
- 슬라이드당 대본이 **25초~110초** 안인가 — 110초를 넘으면 그건 슬라이드가 아니라 문서다
- 글자 크기 하한(본문 24px / 코드 20px) 위반이 있는가
- 복사해 온 SVG의 `data-at` 프레임 수와 `wireDia` 단계 수가 **일치하는가** — 원본에서도 어긋나면
  조용히 깨지는 자리다
- 자산이 **등록된 장에 실제로 놓여 있는가** — `registerBeats('s07', wireDia('diaGate'…))` ·
  `registerBeats('a02', createSequence('nativeSeq'…))` · `ON_ENTER['s17'] = seq17` 세 갈래를
  다 본다. 어긋나도 화면에는 아무 표시가 없다: 등록된 장에는 자산이 없는데 비트 수만 자산의
  것이라 `→` 를 눌러도 아무 일이 없고, 자산이 놓인 장에는 구동기가 없어 첫 프레임에 멈춘다
- 죽은 CSS — 기존 `tools/check_dead_css.py` 재사용

### 눈 검사

`O` 개요 그리드로 **글자만 빽빽한 슬라이드**를 찾아낸다. 발표 자료가 문서로 되돌아가는 실패는
여기서 한눈에 보인다.

**"한 화면"은 아니다.** 67장은 6칸 기준 1.83화면이고, 칸을 좁혀도 한 화면이 되지 않는다
(7칸 1.66 · 10칸 1.44 — 좁아지면 제목이 더 줄바꿈해서 행 높이가 같이 오른다). 한 화면에
넣으려면 칸에서 제목을 빼야 하는데, 그러면 '어느 장이 빽빽한가'를 보는 도구가 아니게 된다.
그래서 **스크롤을 인정한다.** 대신 이 화면이 도구로 쓰이려면 두 가지가 성립해야 한다:
열었을 때 **지금 서 있는 칸이 보일 것**, 그리고 **화살표로 굴러갈 것**(창 뒤에서 슬라이드가
넘어가지 않을 것). 둘 다 테스트가 지킨다.

### 완주 검사

브라우저에서 `→`만 눌러 처음부터 끝까지. 프레임 소진 후 슬라이드로 넘어가는 로직이 67장 내내
끊김 없이 도는지.

## 11. 작업 순서

1. 설계 문서 커밋
2. **덱 골격** — CORE CSS/JS + 표지 + 빈 슬라이드 53장 + 타이머. 자산 없이 먼저 굴러가는지 확인 ← **확인 지점**
3. 자산 이식 — `.dia` 9개, `mainSeq`, 라이브 데모 6개
4. 본편 슬라이드 콘텐츠
5. 대본 53장 + 시간 맞추기 ← **확인 지점** (합계 숫자 보고)
6. 부록 14장
7. 검사기 + 완주 검사

2번과 5번에서 멈춘다. 골격이 틀렸는데 대본을 다 쓰면 손해가 크고, 대본 합계가 어긋나면 그때 깎는
것이 가장 싸다.

## 12. 파일럿 통과 후 — 나머지 7편

이 설계는 oauth2까지만 확정한다. 통과 후의 방향만 적어 둔다.

- `DECK:CORE:*` 블록을 `tools/build_slides.py`의 템플릿으로 추출
- 문서별 매니페스트(장 선택·시간 배분·자산 id 목록)와 대본만 새로 쓴다
- 문서마다 분량이 달라(`auth_basics.html`은 본문이 oauth2의 두 배가 넘는다) **1회 55분에 안 들어가는
  문서는 2회로 나누는 판단이 매니페스트 단계에서 필요하다.** 그 판단은 문서별로 따로 받는다
- `index.html`에 덱 링크를 어떻게 노출할지도 이때 정한다

## 13. 열어 둔 것

- **밝은 테마**: SVG 색 변수 전면 재정의가 필요해 파일럿 범위 밖. 회의실 조명이 문제가 되면 그때 다룬다.
- **PDF 내보내기**: 인쇄 요구가 나오면 `@media print`로 대응. 지금은 필요가 확인되지 않았다.
- **리허설 음성**: 대본 구조를 `tts_script.json`과 맞춰 두므로 가능은 하다. 실제로 뽑을지는 별건.
