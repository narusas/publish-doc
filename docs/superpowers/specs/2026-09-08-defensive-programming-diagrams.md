# 방어적 프로그래밍 문서 · 도해 보강 설계

**날짜:** 2026-09-08
**대상 문서:** `defensive_programming.html`
**선행 설계:** `docs/superpowers/specs/2026-09-07-defensive-programming-design.md` (이 문서는 그 설계의 보강이며, 거기서 세운 제약은 전부 그대로 유효합니다)

---

## 1. 왜 하는가

완성된 문서를 사용자가 읽고 남긴 지적은 하나입니다. "이미지, 다이어그램으로 표현 하는게 더 좋은 부분도 꽤 있는데, 너무 글자와 표만 있음."

측정하면 지적이 그대로 확인됩니다. 같은 시리즈의 다른 문서는 인라인 SVG 도해를 아홉 장에서 열세 장까지 싣고 있는데, 이 문서만 한 장도 없습니다.

| 문서 | SVG | 표 |
|---|---|---|
| `rbac_tutorial.html` | 13 | 9 |
| `auth_basics.html` | 10 | 0 |
| `oauth2_tutorial.html` | 10 | 3 |
| `aws_basics.html` | 9 | 10 |
| **`defensive_programming.html`** | **0** | **2** |

열아홉 개 섹션이 전부 산문과 코드 블록과 조작형 데모로만 이루어져 있습니다. 데모 열두 개가 상호작용을 맡고 있지만, 데모는 누른 결과를 보여 주는 물건이지 구조를 한눈에 보여 주는 물건이 아닙니다. 공간 관계와 시간 순서를 다루는 대목이 전부 문장으로만 서 있습니다.

## 2. 무엇을 만드는가

도해 열 장을 넣습니다. 새 체계를 만들지 않고, 저장소에 이미 있는 도해 체계를 그대로 씁니다.

기존 체계의 구성은 이렇습니다.

- 마크업: `<figure class="dia" id="...">` 안에 `.dia-top`(제목표와 재생 버튼과 단계 점), `.dia-hint`, `.dia-scroll > svg`, `.dia-cap`(단계 설명), `<figcaption>`(그림이 주장하는 것 한 줄)
- SVG: `viewBox="0 0 720 N"`, `role="img"`, 그림 전체의 뜻을 담은 `aria-label` 한 벌
- 단계 표시: 그 단계에서만 보여야 할 요소에 `data-at="0,2"` 또는 `"1-3"` 또는 `"2+"`
- 구동기: `wireDia(id, steps)` 하나가 단계 번호를 `data-s`에 적고, 해당 요소에 `.vis`를 걸고, 단계 설명을 갈아 끼웁니다. 자리와 모양은 구동기가 모릅니다.
- 자동 재생: `IntersectionObserver`로 화면에 들어와 있는 동안에만 돕니다. 손으로 멈춘 것은 다시 들어와도 저절로 돌지 않습니다.
- 접근성: `prefers-reduced-motion`을 존중해 마지막 단계를 세워 두고, 단계를 손으로 넘기는 것만 남깁니다.

## 3. 도해 열 장

각 도해는 두 조건을 모두 만족해야 채택됩니다. 첫째, **지금 산문이 혼자 지고 있는 것**을 대신 져야 합니다. 둘째, **기존 데모 열두 개와 겹치지 않아야** 합니다. 데모가 이미 조작으로 보여 주는 것을 그림으로 한 번 더 그리면 분량만 늘고 독자는 같은 것을 두 번 봅니다.

| 번호 | 자리 | 대응 소제목 | 그림이 지는 것 |
|---|---|---|---|
| D1 | 1장 `trace` | 📏 터진 자리와 잘못된 자리 | 호출 스택 열 줄을 세로로 세우고, 예외가 터진 자리는 정확히 표시하되 값이 잘못된 자리는 이 열 줄 **바깥**에 있음을 보인다. 원인을 모르므로 바깥쪽은 후보 세 갈래로 열어 둔다. |
| D2 | 3장 `silent` | 🫥 조용한 실패의 다섯 가지 모습 | 같은 잘못된 값이 다섯 지점을 지나며 지점마다 다른 방식으로 조용해지는 그림. 다섯 항목이 지금 목록이다. |
| D3 | 4장 `boundary` | 🔬 검증 위치를 옮겨 보기 | 검증 지점을 파싱·캐시·조립·렌더 네 자리로 옮길 때마다, 잘못된 값이 갈 수 있는 **거리**와 스택 줄 수와 메시지에 실리는 맥락이 함께 줄어드는 그림. |
| D4 | 5장 `invariant` | 🕳️ 무엇이든 담기는 모델이 치르는 대가 | `Map<String,Object>`·검증 없는 DTO·생성자가 강제하는 DTO 세 모델이 **표현할 수 있는 상태의 넓이**가 줄어드는 그림. 검사 코드가 오히려 줄어드는 이유가 여기서 보인다. |
| D5 | 6장 `assembly` | 📤 응답이 이미 나간 뒤 | 시간축 위에 응답 커밋 지점을 찍고, 그 뒤에 난 예외는 아무리 넓게 감싸도 상태 코드를 되돌리지 못한다는 것을 보인다. 산문만으로 서 있고 데모가 다루지 않는 대목이다. |
| D6 | 7장 `swallow` | 🎣 같은 예외, 네 층 | 예외 하나가 파서에서 전역 처리기까지 네 층을 올라가며, 층마다 **대안이 있는지**에 따라 자격이 갈리는 세로 그림. |
| D7 | 9장 `slowdown` | 🧵 스레드 풀이 마르는 순서 | 느린 섹션에 걸린 요청이 스레드를 하나씩 붙들어 풀이 마르고, 그 섹션과 무관한 요청까지 대기열에 걸리는 과정. 예외가 하나도 없는데 전체가 서는 이유가 여기서만 보인다. |
| D8 | 9장 `slowdown` | 🧮 예산에서 거꾸로 나눈 타임아웃 | 상위 예산 막대를 먼저 세우고 그것을 섹션으로, 다시 연결 몫과 읽기 몫으로 나누는 그림. 짧게 잡을수록 정상 흔들림과 실제 실패를 가르는 눈금이 좁아지는 것도 같은 막대 위에 표시한다. |
| D9 | 11장 `specgap` | 🖍️ 다섯 줄을 다시 읽으면 | 각색한 화면 정의서 다섯 줄을 왼쪽에 세우고, 줄마다 정상 경로는 채워져 있고 실패 경로 자리는 비어 있음을 오른쪽에 나란히 보인다. 다섯 개의 빈자리가 우연이 아니라 구조라는 것이 그림의 주장이다. |
| D10 | 15장 `recap` | 🗺️ 반경 지도, 이번에는 구멍까지 | 여섯 반경을 동심 띠로 그리고, 반경마다 막는 것과 그럼에도 남는 구멍을 표시한다. 소제목이 이미 '지도'인데 지금은 카드 목록이다. |

## 4. 구속 조건

### 4.1 선행 설계에서 그대로 이어지는 것

- **각색 유지.** 사내 식별자를 쓰지 않습니다. `bannerImageList`·`mainSections_jsp`·`SectionContent` 등 문서가 이미 쓰고 있는 각색된 이름만 씁니다. 반대로 증거로 쓰기로 한 것(`javax.el`, `BeanELResolver`, `9946`, `_005fset_005f141`)은 그대로 유지합니다.
- **원인 단정 금지.** 이번 장애의 원인은 아직 모릅니다. 그림이 원인을 하나로 지목해서는 안 됩니다. D1 은 후보를 세 갈래로 열어 두고, D3 은 네 자리를 가정으로 명시합니다. **그림 안의 글자도 산문입니다.** 화면에 찍히는 라벨 한 조각이 단정하면 문장이 단정한 것과 같습니다.
- **한국어 문장 규칙.** `~/.claude/output-styles/fluent-korean.md`를 따릅니다. 단계 설명과 캡션은 완성된 문장으로 끝맺습니다.

### 4.2 이 작업에서 새로 걸리는 것

- **CSS 는 쓰는 것만 가져온다.** `tools/check_dead_css.py`가 정의됐지만 쓰이지 않는 클래스를 실패로 잡습니다. 형제 문서의 `.dia` CSS 를 통째로 복사해 오면 실패합니다. 실제로 쓰는 클래스만 추려서 가져오고, 컴포넌트 CSS 는 그것을 처음 쓰는 태스크가 함께 가져옵니다.
- **문자열로 조립한 클래스명은 검사기에 보이지 않는다.** `class="band ${tone}"` 같은 보간은 `check_dead_css.py`가 정의 쪽만 보고 사장 CSS 로 판정합니다. 상태별 리터럴로 씁니다. 이 문서를 지을 때 이미 세 번 밟은 함정입니다.
- **반경 지도의 단일 출처를 지킨다.** `RADIUS` 배열 하나가 개요와 15장 양쪽을 그리고 있고, 코드에 "두 그림이 어긋날 수 없는 이유가 이 두 줄이다"라는 주석이 붙어 있습니다. D10 은 그 배열에서 그립니다. 그림에 문구를 따로 적어 두면 그 불변식이 깨집니다.
- **장마다 `.oneline`은 정확히 하나.** 도해를 넣으면서 강조 상자를 새로 만들지 않습니다.
- **`figcaption`은 그림이 주장하는 것 한 줄이고, `.dia-cap`은 단계마다 바뀝니다.** 둘을 같은 내용으로 채우지 않습니다.

## 5. 접근성

- SVG 마다 `role="img"`와 `aria-label` 한 벌을 답니다. 라벨은 그림 전체가 무엇을 주장하는지를 문장으로 적습니다. 도형 목록을 나열하지 않습니다.
- 단계 설명(`.dia-cap`)은 `aria-hidden`으로 덮습니다. 자동 재생이 도는 내내 화면 낭독기가 계속 읽으면 본문을 들을 수 없기 때문입니다.
- `prefers-reduced-motion: reduce`인 사용자에게는 자동 재생을 걸지 않고 마지막 단계를 세워 둡니다. 단계를 손으로 넘기는 것은 남깁니다.
- 좁은 화면에서는 그림을 통째로 줄이지 않고 최소 폭을 준 뒤 그림 상자 안에서만 가로로 흘립니다. 720 짜리 그림을 400 에 밀어 넣으면 12.5px 글자가 7px 가 되어 읽을 수 없습니다.

## 6. 검증

- `python3 tools/check_tutorial.py defensive_programming.html`이 통과해야 합니다.
- `python3 tools/check_dead_css.py defensive_programming.html`이 통과해야 합니다.
- 기존 테스트 115개가 전부 통과해야 합니다.
- 도해 전용 테스트를 더합니다. 정적 검사는 도해 개수와 `data-at` 표기의 유효성, `aria-label` 존재, `figcaption` 존재, 각색 금칙어 부재를 봅니다. 동작 검사는 브라우저에서 `wireDia`가 단계를 실제로 넘기는지, 단계 점 개수가 `steps` 길이와 같은지, `prefers-reduced-motion`에서 자동 재생이 걸리지 않는지를 봅니다.
- 브라우저가 없으면 건너뛰지 않고 실패합니다. 이 저장소의 기존 규칙입니다.

## 7. 하지 않는 것

- 래스터 이미지를 넣지 않습니다. 이 문서는 외부 의존이 없는 단일 HTML 이고, `check_tutorial.py`가 외부 리소스 로드를 실패로 잡습니다. 도해는 전부 인라인 SVG 입니다.
- 기존 데모 열두 개를 고치지 않습니다. 도해는 데모를 대체하지 않고 데모가 다루지 않는 자리를 맡습니다.
- 개요의 반경 지도 카드 목록은 그대로 둡니다. 개요는 문서를 펼치는 자리라 압축된 목록이 맞고, 구멍까지 그리는 것은 15장의 몫입니다.
