# AWS 기초 튜토리얼 — 설계 문서

- 날짜: 2026-08-15
- 산출물: `aws_basics.html` (신규), `index.html` (카드 추가)
- 시리즈: 인터랙티브 개발 튜토리얼 모음 (8번째 문서)

## 1. 왜 만드는가

시리즈에 AWS 문서가 둘 있는데, 둘 다 같은 것을 전제하고 시작한다.

- `iam_tutorial.html` — "누가 무엇을 할 수 있나". **리소스·ARN·계정이 무엇인지 안다**고 보고 출발한다.
- `aws_network_security.html` — "패킷이 어디까지 가나". 2장에서 VPC를 발판으로 깔지만
  **통제의 발판**일 뿐이고, EC2·EBS·S3·요금은 다루지 않는다.

전수 검사 결과 시리즈 7개 문서에서 다음이 실질적으로 0회다.

| 개념 | 등장 |
|---|---|
| 가용 영역(AZ) | 0회 |
| EBS | 0회 |
| 요금 | `iam` 0회, `aws_network_security` 9회(전부 Endpoint 비용 맥락) |
| 청구 | `iam` 5회(계정=청구 단위라는 언급뿐) |
| CLI | 각 1~2회 |
| RDS | `iam` 0회 |

즉 **"AWS의 구성 자체"가 시리즈의 빈 칸**이고, AWS 3종의 **맨 앞자리**가 이 문서다.
읽는 순서는 `aws_basics` → `iam_tutorial` → `aws_network_security`가 된다.

## 2. 척추

> **"서버 한 대를 빌린 줄 알았는데, 콘솔에는 리소스가 아홉 개 생겨 있었다."**

AWS의 구성이란 곧 **한 덩어리였던 것이 무엇 무엇으로 쪼개졌는가**이고, 그 쪼갬의 규칙을 익히면
나머지 서비스도 같은 규칙으로 읽힌다. 아홉 개 목록이 히어로에서 제시되고, 1부의 각 장이
하나씩 정체를 밝혀 지워 나간다.

**전개 방식**: 해체 → 재조립. 1부는 "왜 이것만 따로 떨어져 나왔나", 2부는 "그 부품으로 어떻게 짓나".

기각한 두 가지:

- **청구서 역추적** — 요금 순서와 개념 의존 순서가 어긋난다. NAT Gateway가 청구서 상위에
  오는데 그걸 이해하려면 서브넷·라우팅이 먼저다. 초심자에게 순서가 뒤엉킨다.
- **요청 한 건의 여정** — 계정·리전·ARN·요금·IaC가 그 길 위에 없어 억지로 끼우거나 버려야 한다.
  게다가 이 전개는 `network_basics.html`이 이미 쓰고 있다.

## 3. 무대

`iam_tutorial.html`의 "나루 클라우드"를 그대로 쓰되 **시계를 되감는다.** 김주임이 입사 후
첫 서비스를 올리는 시점이다. 박팀장·이보안은 배경에 두고, 주인공은 김주임 하나로 좁힌다.
독자가 이 문서를 다 읽고 IAM 문서를 열면 같은 사람의 몇 달 뒤가 된다. 세계관 학습 비용이 0이다.

## 4. 독자와 선수 지식

- 대상: **앱은 짜봤고 서버는 모르는** 주니어. 프로세스·포트·파일시스템·HTTP는 쓰지만,
  서버를 장비로 생각해 본 적이 없다.
- 전제하지 않는 것: 서버·디스크·랜카드의 물리적 구분, VM, 가상화, VPC, IAM, 클라우드 요금 모델.
- 전제하는 것: 웹 앱을 만들어 로컬에서 띄워 본 경험. HTTP 요청/응답. 터미널 기본기.
- 난이도 표시: 제목 옆 🟢 필수 / 🔵 심화 (`iam_tutorial.html`의 `.lvl` 패턴).

## 5. 구성 — 15장 + 부록 2

### Hero · "한 대를 주문했는데 아홉 개가 생겼다"

30초 자가진단(`.diag`) → 무대 소개(김주임) → 아홉 개 목록 → 지도(`.map-grid`) → 읽는 법.
아홉 개 목록이 문서 전체의 미결 목록이 된다.

### 1부 · 한 대가 무엇 무엇으로 쪼개졌나

#### 1장 · 🧩 아홉 개의 정체 — 왜 쪼개 놓았나 🟢
- 온프렘 서버 한 대 안에서 한 몸이던 것들(CPU·디스크·랜카드·전원)이 AWS에서는 각각
  **따로 생기고 따로 죽고 따로 과금된다**.
- 쪼갠 이유는 셋: 수명을 따로 두려고 · 값을 따로 매기려고 · 다시 조립하려고.
- **데모**: 해체기 — "서버 한 대"를 누르면 아홉 조각으로 흩어지고, 조각마다 수명·과금이 붙는다.

#### 2장 · 🪣 계정 — 모든 것이 담기는 그릇 🟢
- 계정은 **격리 단위이자 청구 단위**다. 리소스는 반드시 계정 하나에 속한다.
- 루트 계정과 그 외. (권한 이야기는 IAM 문서로 넘기고, 여기서는 "그릇"까지만)
- 계정이 다르면 기본은 서로 보이지 않는다.
- **데모**: 계정 경계 판정기 — dev 계정의 EC2가 prod 계정의 S3를 읽을 수 있나.

#### 3장 · 🌏 리전과 AZ — 왜 자꾸 어디냐고 묻는가 🟢
- 리전은 **서로 격리된 별개의 세계**다. 서울에서 만든 것은 도쿄 콘솔에 보이지 않는다.
- AZ는 리전 안의 건물. 서브넷은 AZ에 갇힌다(→ 7장, 9장에서 회수).
- 글로벌인 것들의 예외(S3 버킷 이름, IAM, CloudFront, Route 53).
- **오해 격파**: `ap-northeast-2a`는 **계정마다 다른 건물**을 가리킨다. (V6)
- **데모**: 리전·AZ 지도.

#### 4장 · 🏷️ ARN — AWS가 물건을 세는 법 🟢
- 리소스는 전부 이름표를 하나씩 갖는다. 그 이름표의 문법이 ARN이다.
- 파티션·서비스·리전·계정·리소스 — 그리고 **비는 칸이 있는 이유**. IAM은 전역이라 리전이 비고,
  S3는 버킷 이름이 파티션 전역에서 유일하니 계정까지 빈다. 파티션은 **개수를 숫자로 쓰지 않는다**
  — 공식 문서 두 곳이 셋과 넷으로 어긋나 있다. (V11)
- 이름(name)과 ID(`i-0abc…`)의 차이. 콘솔이 보여 주는 것과 API가 쓰는 것이 다르다.
- **회수 예고**: 여기서 익힌 ARN이 13장 API 호출의 `Resource` 자리이고, IAM 문서의 정책 전부가
  이 문법 위에 서 있다.
- **데모**: ARN 해부기 — 리소스 종류를 바꾸면 어느 칸이 비는지. (V11)

#### 5장 · 🖥️ EC2 — 인스턴스는 서버가 아니다 🟢
- AMI(틀) → 인스턴스(찍어 낸 것). 인스턴스 타입은 **장비 사양의 이름표**다.
- 상태 넷: running · stopped · terminated · rebooting.
- **stop과 terminate는 다른 일이다.** 무엇이 살아남고 무엇이 사라지는지가 갈린다.
- 인스턴스 스토어와 EBS의 차이가 여기서 처음 드러난다. (V8)
- **데모**: 인스턴스 상태 기계 — 상태를 옮기며 퍼블릭 IP·인스턴스 스토어·EBS의 생사를 본다.

#### 6장 · 💽 EBS — 디스크가 따로 노는 이유 🟢
- 볼륨은 인스턴스 밖에 있고, 붙였다 뗄 수 있다. 그래서 **인스턴스를 지워도 남을 수 있다**.
- `DeleteOnTermination`의 기본값은 **축이 셋**이다 — 볼륨 종류, 언제 붙였나, 그리고 **콘솔이냐
  CLI냐**. 같은 "시작할 때 붙인 데이터 볼륨"인데 콘솔은 남기고 CLI는 지운다. 최종 결정권은
  AMI에 있으므로 "기본값은 X다"라고 단정하지 않는다. (V3)
- 이 갈림은 13장("콘솔·CLI·API는 같은 문")과 부딪히는 것처럼 보이지만 모순이 아니다. 문은
  하나이고 **콘솔이 대신 채워 넣는 값이 다를 뿐**이다. 두 장을 잇는 데 쓴다.
- 스냅샷은 증분이고 S3에 저장된다.
- **회수 예고**: 12장 청구서의 정체불명 EBS가 여기서 생긴다.
- **데모**: 볼륨과 스냅샷 — 인스턴스를 지웠을 때 볼륨이 남는 조건.

#### 7장 · 🔌 ENI — 랜카드가 리소스가 되면 🟢
- 네트워크 인터페이스가 별도 리소스다. 사설 IP는 ENI에 붙고, 퍼블릭 IP는 붙지 않는다.
- 그래서 **stop 후 start하면 퍼블릭 IP가 바뀐다**. EIP가 필요한 이유. (V1)
- ENI는 서브넷에 속하고 서브넷은 AZ에 갇히므로, **인스턴스는 AZ를 옮길 수 없다**. (3장 회수)
- SG는 여기 붙는다 — 이름만 걸어 두고 `aws_network_security.html`로 인계.
- **데모**: ENI 붙였다 떼기.

#### 8장 · 🗄️ S3 — 파일 서버가 아니다 🟢
- 버킷과 키. 디렉터리는 없다 — 슬래시가 든 이름이 있을 뿐.
- **객체는 통째로 쓰고 통째로 읽는다.** 일부만 고칠 수 없고, 마운트해서 쓰는 물건이 아니다.
- 버킷 이름은 파티션 전역에서 유일하다. (V5) — 3장 "글로벌인 것들"의 회수.
- EBS와 갈리는 축: 접근 방식(블록 vs HTTP API), 동시 접근, 수명.
- **데모**: S3 vs EBS — 같은 작업(일부 수정·동시 접근·마운트)을 양쪽에 시켜 본다.

### 2부 · 다시 조립하기

#### 9장 · 🚪 앞에 무엇이 서 있나 🟢
- IGW — 퍼블릭 IP를 가진 것만 지나간다. NAT GW — 나가기만 하는 문.
- ALB(HTTP를 읽는다) vs NLB(포트만 본다). 무엇을 보느냐가 첫 번째 갈림길이다.
- 두 번째 갈림길은 **주소**다. NLB는 AZ마다 EIP를 지정해 고정 IP를 가질 수 있고, ALB의 주소는
  서비스가 쥐고 있어 바꾸거나 놓아줄 수 없다. "상대 방화벽에 우리 IP를 등록해야 한다"가
  NLB를 고르는 실제 이유가 된다. (V7)
- **ALB는 서로 다른 AZ의 서브넷을 최소 둘 요구한다** (V7) — 3장 AZ와 7장 ENI가 함께 회수된다.
- 로드밸런서가 앞에 서면 **인스턴스에 퍼블릭 IP가 필요 없어진다**.
- 통제(무엇을 막을까)는 다루지 않는다. 그건 `aws_network_security.html`이다.
- **데모**: 입구 고르기 — 요구사항을 넣으면 IGW·NAT GW·ALB·NLB 중 무엇이 필요한지.

#### 10장 · 🤝 관리형 — 무엇을 남기고 무엇을 가져가는가 🟢
- RDS를 예로, **AWS가 가져가는 일**과 **내게 남는 일**의 분계선을 긋는다.
- 가져가는 대신 **못 하게 되는 것**이 생긴다 — OS 접근, superuser, 임의 확장 설치. (V10)
- 책임 공유 모델을 여기서 이름 붙인다(이론을 먼저 내지 않고, 분계선을 본 뒤에).
- **데모**: 책임 분계선 — 온프렘→EC2→RDS로 옮기며 줄어드는 일과 못 하게 되는 일.

#### 11장 · 📦 내 앱을 어디에 올리나 🟢
- 세 갈래: EC2(장비를 빌린다) · 컨테이너(프로세스를 맡긴다) · Lambda(함수만 던진다).
- 각각의 **단위**가 다르다 — 인스턴스 / 태스크 / 실행 한 번.
- 갈림의 축: 상시인가 간헐인가, 상태가 있나, 기동 시간을 견딜 수 있나, 실행 한계.
  한계는 **"Lambda 함수의 타임아웃은 900초"**로 대상을 좁혀 쓴다 — "Lambda는 15분이 최대"는
  같은 문서의 MicroVM 항목과 어긋난다. (V9)
- ECS·Fargate·EKS·Lambda는 개념 수준까지만. 설정법은 다루지 않는다.
- **데모**: 세 갈래 선택기.

#### 12장 · 💸 안 쓰는데 돈이 나간다 🟢
- 1장에서 쪼갠 아홉 개가 **각각 따로 과금된다**는 것의 청구서 쪽 얼굴.
- 껐는데도 나가는 것: 정지한 인스턴스의 EBS, 퍼블릭 IPv4, NAT Gateway, 남은 스냅샷.
- **"안 쓰는 EIP에만 돈이 나간다"는 낡은 상식이다.** 2024년 2월부터 쓰는 것과 노는 것의 시간당
  값이 같으므로, 축은 "붙였나 놀리나"가 아니라 **"몇 개나 갖고 있나"**다. (V2)
- NAT Gateway는 세 겹이다 — AZ 수만큼의 시간당 요금 + 처리 GB당 요금 + 자신이 쥔 퍼블릭 IPv4. (V4)
- 시간당인 것과 요청당인 것과 GB당인 것. 데이터 전송은 **나가는 방향**이 비싸다.
- 5·6·7·9장에서 심은 것이 전부 여기로 모인다.
- **데모**: 요금 계산기 — 껐는데도 나가는 항목만 붉게.

#### 13장 · 🚪 콘솔·CLI·API는 같은 문 세 개 🟢
- 콘솔 클릭도, `aws` 명령도, SDK 호출도 **밑에서는 같은 API 하나**다.
- 그래서 콘솔에서 되는 것은 전부 자동화할 수 있다.
- 자격 증명이 어디서 오는가(환경변수·프로필·인스턴스 역할) — 이름만 걸고 IAM 문서로 인계.
- 4장 ARN이 API 요청의 `Resource` 자리에서 다시 나온다.
- **데모**: 같은 일 세 가지 방법 — 아래 깔린 API 호출이 하나임을 보인다.

#### 14장 · 🧾 손으로 만든 것은 사라진다 🟢
- 콘솔에서 클릭한 아홉 개를 누가 기억하는가. 태그가 없으면 **청구서의 항목이 익명이 된다**.
- 태그의 실제 쓸모: 비용 배분, 소유자 추적, 일괄 조작.
- IaC(CloudFormation·Terraform)는 개념까지 — "만든 순서가 파일로 남는다".
- 드리프트: 콘솔에서 손으로 고치면 어떻게 되는가.
- **데모**: 드리프트 시뮬레이터.

#### 15장 · 🏁 마무리 — 내 계정에는 지금 몇 개가 켜져 있나
- 체크리스트(`.ckl`) + 히어로 아홉 개 회수.
- 두 문서로 인계: "누가 만질 수 있나"는 IAM, "패킷이 어디까지"는 네트워크 보안.

| 3장 글로벌인 것들 | 8장 버킷 이름은 파티션 전역에서 유일 |
| 5장 stop하면 퍼블릭 IP가 바뀐다 | 9장 EIP → 12장 안 붙여 둔 EIP에 돈이 나간다 |
| 6장 인스턴스를 지워도 볼륨이 남는다 | 12장 청구서의 정체불명 EBS |
| 4장 ARN | 13장 API 호출의 `Resource` → IAM 문서 전체 |
| 1장 따로 과금된다 | 12장 청구서 |
| 2장 계정은 격리 단위 | 10장 책임 분계선 → IAM 문서 |

## 7. 문체 규범

`/cognitive-rhythm-writing` 규범을 적용해 쓴다. 구현·퇴고 양쪽에 적용되는 조건이다.

- 리듬은 정보량이 아니라 **인지 모드의 전환**(관찰→주저→단정→재관찰)으로 만든다.
- 항상 최소 하나의 **답하지 않은 질문**을 열어 둔다. 히어로의 아홉 개가 그 역할을 하고,
  1부가 끝날 때 "그래서 이걸로 뭘 짓나"가 새로 열린다.
- 절 첫머리에 "이 절에서는 ~를 다룬다"를 쓰지 않는다. 절 끝에 "다음은 ~를 본다"를 붙이지 않는다.
- 본문 자체를 화제로 삼는 문장(진행 예고, 범위 선언)은 삭제한다. 이완은 상황 쪽
  (김주임의 판단, 콘솔에 실제로 벌어진 일, 수치)에서만 가져온다.
- 나열은 나열로 끝내지 않고 직전의 구체적 장면에 하나씩 착지시킨다.
- 같은 어미를 세 문장 연속으로 쓰지 않는다.
- 시리즈 톤은 존댓말 서술을 유지한다(기존 7종과 동일).
